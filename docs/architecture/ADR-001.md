# ADR-001 — ModularAI como plataforma de distribución e integración

## Estado

Aceptado.

## Contexto

Los proyectos y agentes necesitan combinaciones distintas de metodología, conocimientos, memoria, herramientas y harness. Integrar una selección concreta en el servidor acoplaría el producto a un flujo y duplicaría responsabilidades de herramientas existentes.

## Decisión

ModularAI será una plataforma local, modular y agnóstica de modelos y agentes. El núcleo contiene el registro inmutable de paquetes, la resolución de dependencias, el almacenamiento de artefactos, la recuperación de conocimiento y el contrato de memoria.

SDD, ODD, RDD, harnesses, skills, MCP, plantillas, conocimientos, adaptadores de memoria y modelos son paquetes independientes instalables en un proyecto. Ninguno es dependencia obligatoria del núcleo.

La primera implementación se distribuye como contenedor multi-arquitectura compatible con ARM64 y expone una API HTTP local. La CLI es multiplataforma y materializa únicamente los archivos declarados por cada paquete.

## Consecuencias

- El servidor puede funcionar con un registro vacío.
- Los perfiles son paquetes de composición; no son lógica especial del núcleo.
- Un cambio de harness no obliga a migrar el servidor.
- La búsqueda inicial usa SQLite FTS5; un proveedor vectorial puede añadirse después sin sustituir el gestor de paquetes.
- La CLI debe proteger archivos del usuario. Solo elimina un archivo administrado si su hash sigue siendo el instalado.
